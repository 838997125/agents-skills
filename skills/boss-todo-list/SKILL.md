# Boss Todo List - 多智能体任务协作技能

## 技能概述

本技能实现复杂任务的多智能体协作执行：由高级项目经理（PM）自主分析任务需求，在 `D:\agency-agents-zh` 项目中扫描可用角色，根据任务模块选择最合适的角色并行/顺序执行，最后由 PM 汇总整合成完整交付物。

## 核心价值

- **自主角色选择**：PM 根据任务需求在 AGENT-LIST.md 中自主匹配角色，无需用户逐个指定
- **任务模块化拆分**：复杂任务拆分为独立模块，并行执行提升效率
- **质量把控**：PM 审核各角色输出，确保一致性、合规性和主题相关性
- **可追溯记录**：保留各角色输出记录，便于审计和迭代

## 执行流程

### 步骤 1：项目经理任务规划

当用户触发技能时，激活 **高级项目经理** (`project-manager-senior`) 执行：

```
1. 理解任务目标
   - 明确用户的核心需求和期望产出
   - 识别任务的范围和边界

2. 识别任务模块
   - 将复杂任务拆分为独立的模块
   - 确定模块间的依赖关系

3. 确定角色需求
   - 根据每个模块的专业要求，确定需要哪些角色
   - 在 D:\agency-agents-zh\AGENT-LIST.md 中查找匹配的角色

4. 制定执行计划
   - 安排各角色的任务顺序（并行/顺序）
   - 定义各角色的输入要求和输出格式
   - 设置质量控制检查点

5. 输出任务分配表
   - 每个模块指定负责角色
   - 明确交付物格式和截止时间
```

### 步骤 2：扫描项目查找可用角色

项目路径：`D:\agency-agents-zh`

**扫描 AGENT-LIST.md 获取可用角色列表：**

```
1. 读取 D:\agency-agents-zh\AGENT-LIST.md
2. 识别所有部门分类（工程部、设计部、营销部、金融部、项目管理部等）
3. 根据任务需求匹配角色：

任务类型 → 匹配部门/角色：
─────────────────────────────────────────────
市场分析/竞品研究     → 营销部、战略部
技术方案评估         → 工程部
财务预测/ROI分析     → 金融部
运营策略/增长路径    → 营销部、销售部
用户研究/体验优化    → 设计部（UX）
合规审核/法律审查    → 法务部
供应链/采购优化      → 供应链部
人力资源规划         → 人力资源部
```

**角色选择决策记录格式：**

```
| 模块 | 选择角色 | 选择理由 | Agent ID |
|------|---------|---------|----------|
| 市场机会分析 | 抖音策略师 | 抖音平台专家，熟悉医药电商赛道 | marketing-domestic-trends-analyst |
| ... | ... | ... | ... |
```

### 步骤 3：并行/顺序执行各角色任务

**任务执行模式：**

| 模式 | 适用场景 | 说明 |
|------|---------|------|
| 并行执行 | 独立模块（如市场分析、技术评估、财务预测可同时运行） | 同时激活多个角色，提升效率 |
| 顺序执行 | 有依赖关系的模块（先市场分析，再运营策略） | 前序输出作为后续输入 |
| 混合执行 | 部分并行+部分顺序 | 根据任务图谱确定执行顺序 |

**角色任务卡模板：**

每个被激活的角色必须接收以下格式的任务卡：

```markdown
## 角色任务卡

**角色名称**：[从 AGENT-LIST.md 选择的专业角色]
**负责模块**：[具体模块名称]
**核心问题**：[需要回答的 3-5 个核心问题]

**输入要求**：
1. [必须提供的数据/分析内容]
2. [具体的数据来源或案例要求]
3. [任何前置依赖或上下文信息]

**输出格式**：
- 字数要求：X-Y 字
- 必须包含：数据图表 X 个、结论要点 X 条
- 格式模板：[具体格式要求]

**合规要求**：
- [如有行业合规要求需特别说明，如医药广告法、金融监管等]

**质量标准**：
- 所有结论必须包含数据来源或案例依据
- 模糊表述需量化支撑
- 偏离主题的内容将被驳回
```

### 步骤 4：项目经理汇总整合

PM 在收集所有角色输出后执行：

```
1. 内容审核
   - 检查数据一致性和结论支撑
   - 确保格式统一
   - 验证假设前提透明度

2. 合规性审核
   - 特殊行业（医药、金融、法律等）需通过专项合规检查
   - 功效声称边界、监管红线等

3. 风格统一
   - 统一报告结构和表达风格
   - 消除矛盾结论

4. 质量把控（偏离管控）
   - 如有内容偏离主题，PM 需提出具体修改意见
   - 修改意见应包含：偏离原因、期望方向、修改建议
   - 将修改意见反馈给对应角色，要求根据意见重新生成输出
   - 重新生成的输出需再次经过 PM 审核，直到通过为止

5. 输出整合报告
   - 完整的整合报告
   - 各模块原始输出（附录）
   - 数据来源清单
   - 质量控制记录（含修改意见和迭代记录）
```

**修改意见反馈模板：**

```markdown
## 修改意见单

**角色名称**：[被审核角色]
**模块名称**：[输出模块]
**审核结果**：❌ 未通过

**偏离问题**：
[具体说明内容偏离主题的部分]

**修改意见**：
1. [第一条修改建议]
2. [第二条修改建议]
...

**期望方向**：
[说明最终输出应该呈现的方向和风格]

**截止时间**：[重新提交的截止时间]
```

**质量标准：**
- 所有结论必须包含数据来源或案例依据
- 模糊表述需量化支撑
- 偏离主题的内容将被驳回并要求重新生成
- 每次修改需记录，形成迭代追踪

## 输出规范

### 最终交付物结构

```
# [项目名称] 分析报告

## 执行摘要（1页）
- 核心发现（3-5条）
- 关键建议（优先级排序）

## 三、[模块3名称]

## 附录
- A. 角色任务分配表
- B. 各模块原始输出
- C. 数据来源清单
- D. 质量控制记录
```

### 质量控制标准

| 检查项 | 标准 | 检查方法 |
|--------|------|----------|
| 数据支撑 | 所有结论必须包含数据来源 | 标注引用来源 |
| 格式统一 | 各角色输出符合模板要求 | PM 逐项核对 |
| 合规审核 | 医药/金融等特殊行业通过专项审核 | 行业专家复核 |
| 假设透明 | 预测性结论明确标注假设前提 | 检查假设清单 |
| 偏离管控 | 偏离主题内容被驳回，PM提出修改意见，角色需重新生成 | PM 一票否决 + 修改意见反馈 |

## 技能使用示例

**用户输入：**
> "我需要一份医药电商抖音短视频AI视频生产的项目分析报告，目标是将日均视频产出从1条提升至50条"

**PM 执行流程：**

1. **任务规划**：识别出6个模块（市场机会分析、竞品研究、技术方案、运营策略、财务预测、执行计划）

2. **角色选择**：根据 AGENT-LIST.md 匹配：
   - 市场机会分析 → 抖音策略师
   - 竞品与用户研究 → 中国电商运营专家
   - AI技术方案评估 → 工具评估师
   - 运营策略 → 增长黑客 + 中国电商运营专家
   - 财务预测 → 财务预测分析师
   - 汇总整合 → 高级项目经理

3. **并行执行**：5个角色同时开始输出各自模块

4. **汇总整合**：PM 收集所有输出，审核、整合成完整报告

**最终输出：**
- 完整的项目分析报告（约 18,000 字）
- 包含数据图表、结论依据、合规声明
- 存放在指定目录（如 `D:\ZYQ工作区\B.项目\`）

## 注意事项

1. **角色自主选择**：PM 应主动扫描 AGENT-LIST.md，基于角色描述和擅长领域进行匹配，而非被动等待用户指定

2. **执行记录**：每次任务执行的角色选择逻辑需记录，便于后续优化角色匹配算法

3. **质量把控**：PM 对所有输出有一票否决权，内容偏离主题将被驳回重新生成

4. **行业合规**：医药、金融、法律等特殊行业的内容必须通过专项合规审核

5. **数据来源**：所有结论必须标注数据来源，预测性结论需明确假设前提
